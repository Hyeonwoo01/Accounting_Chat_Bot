# CLAUDE.md — rag(공시 Q&A) 계층

DART 공시 기반 질의응답. 루트 `CLAUDE.md` 규칙이 우선한다. (가이드 7)

## 구성

- `document_processor.py` (배치): `documents`의 `source_type='dart'` → `## 제목` 기준 절 분할 →
  긴 절은 겹치게 자르기 → 메타데이터 부착 → 임베딩 → 영속 벡터DB. `chunks` 테이블과 같은 `chunk_id` 사용.
- `vector_store.py` (배치): Chroma(LangChain) 영속 저장소, **코사인 공간**. `chunk_id`가 벡터 ID라서
  재실행 시 없는 청크만 임베딩한다. 원문이 바뀐 공시는 그 공시의 벡터를 지우고 다시 넣는다.
- `rag_pipeline.py`: 대시보드가 호출하는 **유일한 공개 인터페이스** (`load_pipeline().ask(질문, company_id=, filing_role=, date_from=, date_to=)`).
  검색 → 답변 → 근거 검증. 대시보드는 `Answer`/`Citation`/`format_citation`만 쓴다.
- 질의 시점에 문서 임베딩을 만들지 않는다 (질문 임베딩만 생성).
- **질문에 법인 하나가 나오면 그 법인 공시로 좁힌다** (`detect_firms`, 별칭은 `company_mapping.yaml`, 띄어쓰기 무시).
  네 법인의 사업보고서가 같은 절 구성이라, 필터 없이 검색하면 법인명을 어떻게 띄어 썼는지에 따라 다른 법인의 표가
  먼저 검색됐다 (2026-11-17: "딜로이트안진회계법인 …"은 거절, "딜로이트 안진 회계법인 …"은 답변). 사용자가
  직접 고른 법인과 질문 속 법인이 다르면 **질문의 법인**으로 찾고 바꾼 사실을 화면에 알린다(`Answer.replaced_company_id`) —
  예시 질문 버튼 등으로 남은 선택값 때문에 엉뚱한 법인을 찾던 문제(2026-11-17). 법인이 둘 이상 나오거나 없으면 선택값을 그대로 쓴다.
- **법인명 오타**는 자모 단위 편집 거리로 고친다 (`fuzzy_firm`: 4자 이상 한글 별칭, 1자모(5자 이상은 2자모)까지,
  가장 가까운 후보가 한 법인일 때만). "삼이회계법인" → 삼일(이↔일 1자모, 이↔정 3자모). 고친 이름으로 검색·답변하고
  `Answer.typo_fixed`로 화면에 알린다. LLM으로 질문을 고쳐 쓰지 않는다 (호출 비용, 결과가 실행마다 달라짐).
- 실행: `scripts/build_vector_store.py` (기본은 비용 추정만, `--run`으로 임베딩),
  `scripts/evaluate_rag.py` (`--retrieval-only` → 기준값 결정, 기본 → 전체 평가, `--score` → 사람 판정 반영).
- 설정: `config/settings.yaml`의 `rag` (청크 크기·k·거절 기준·임베딩 가격). 가격은 가격표로 확인한 값만 적는다.
- LLM 호출에 `temperature`를 보내지 않는다 (gpt-6-luna는 기본값만 허용). 재현성 한계는 리포트에 적는다.

## 검색 방식 (심화, 2026-11-18 — `hybrid.py`, `settings.rag.retrieval`)

- **기본은 `hybrid_rerank`**(2026-11-18 비교 결과, `evaluation/rag_search_comparison.md`). `vector`: 임베딩 검색만. `hybrid`: + BM25 키워드 검색(한글은 단어 안 글자 2-gram), 두 순위를 RRF로 결합.
  `hybrid_rerank`: hybrid 후보(`candidates`개)를 LLM이 질문 관련성 순으로 다시 매겨 k개를 쓴다(질문당 호출 1회 추가).
- 이유: 질문과 공시의 용어가 다르면 벡터 검색이 절을 놓친다(Q04 '조치·제재' vs '감리결과'). 키워드는 겹치는 말을 잡는다.
- **1차 거절은 모든 방식에서 벡터 유사도로 판정**한다(기준값의 의미를 유지). 키워드로만 찾은 청크는 유사도가 없다(`None`).
  거절될 질문에는 리랭킹을 호출하지 않는다.
- BM25 인덱스는 벡터DB의 청크(같은 id·메타데이터)로 프로세스마다 메모리에 만든다(청크 1만 개 기준 약 4초·55MB,
  합성 데이터 측정). 필터(법인·공시 종류·기간)는 벡터 검색과 같은 조건을 메타데이터에 적용한다.
- 방식을 바꾸기 전에 `evaluate_rag.py --mode <방식>`으로 같은 질문을 돌려 사람 판정 후 `--compare`로 비교하고,
  결과를 `evaluation_report.md`에 적는다. `set: holdout` 질문(H01~)은 검색 고도화 뒤 추가한 질문이라 설정을 맞추는 데 쓰지 않는다.

## 대상 문서 (분기 B-1)

- `content`가 있는 DART 문서만 인덱싱한다 (감사보고서는 목록만 있고 원문이 없는 행이 많다).
- 청크마다 **자체 공시인지, 고객사 감사보고서인지**를 메타데이터(`filing_role`: `own` / `audit_client`)로 남긴다.
  판별: `corp_code ∈ get_big4_corp_codes()`이면 `own`.
- 고객사 감사보고서를 근거로 쓸 때 답변과 근거 표시에 **"○○(고객사)의 감사보고서, 감사인 △△"**를 명시한다.
  Big4 자체의 사실처럼 답하지 않는다.
- 고객사명은 `evaluation/audit_originals_sample.csv`(DART `corp_name`)를 우선 쓰고, 없으면 "주주 및 이사회 귀중" 줄에서 찾는다.
- 감사보고서의 **표준 문단**(여러 보고서에 똑같이 나오는 긴 문장)은 청크 전에 뺀다 (`settings.rag.boilerplate_*`).
  남겨 두면 '계속기업' 같은 단어가 든 표준 문장이 검색 상위를 독차지한다. 근거 표시는 뺀 뒤의 청크 원문이고, 전체 원문은 DART 링크로 본다.
- 짧은 절(`min_section_chars` 미만)은 다음 절과 합치고, 모든 청크 앞에 문맥 줄
  `[제출 법인 공시명 | 절 제목]`(감사보고서는 `[고객사 공시명 (감사인 …) | 절]`)을 붙여 임베딩한다.
  표지가 검색을 차지하고 표만 있는 청크가 검색되지 않던 문제(2026-11-16) 때문이다.
- 절 제목은 **상위 제목까지 포함한 경로**다 (`II. 주요사업의 내용 > 2. 외감법에 의한 감사실적 > 가. 감사실적 총괄표`).
  상위 제목은 본문 없이 제목만 있는 경우가 많아, 경로 없이는 표 청크에 하위 제목만 남아 상위 제목의 말로 묻는 질문이
  근거를 찾지 못했다 (2026-11-17, 안진 '외감법에 의한 감사실적' 거절). 단계: `II.` → `2.` → `가.` → `(1)`, 그 밖은 최상위.
- 청크 **메타데이터만** 바뀐 경우(본문 동일)는 변경 감지가 안 되므로 `build_vector_store.py --run --rebuild`로 다시 만든다.
- `company_id`는 두 종류 모두 **제출 법인**이다. 청크의 약 80%가 고객사 감사보고서라서(2026-11-16 추정 실행:
  자체 2,486 / 고객사 9,489) 법인 자체에 대한 질문은 `filing_role='own'`으로 좁힌다. 대시보드도 이 선택지를 둔다.

## 청크 메타데이터 (필수)

`doc_id`, `chunk_id`, `corp_code`, `company_id`, `rcept_no`, `report_nm`, `rcept_dt`, `pblntf_ty`,
`section_title`, `source_url`, `filing_role` — 근거 표시에 그대로 쓰이므로 누락하지 않는다.

## 근거 표시 (가이드 7-3)

- 모든 답변 아래에 공시명, 제출일, 접수번호, 제출 법인, DART 링크, **관련 근거(청크 원문 구절)** 를 표시한다.
- "관련 근거"는 LLM 요약이 아니라 검색된 청크의 원문이다. 인용 구절이 청크에 실제로 있는지
  **문자열 대조**로 확인하고, 일치하지 않는 근거는 표시하지 않는다.
  대조는 **공백만 무시**하고(표 칸이 공백으로 이어져 있어 모델이 띄어쓰기를 바꿈) 나머지 글자는 그대로 맞아야 한다.
  8자 미만 인용은 검증으로 보지 않는다. 불일치 인용은 `Answer.rejected_quotes`로 남겨 화면에서 진단한다.
- 답변에 쓰인 근거만 표시한다.

## 답변 거절 (가이드 7-4)

"수집된 공시에서 근거를 확인할 수 없습니다"로 답하는 경우:

- 최고 유사도가 기준값 미만 → **LLM 호출 없이** 거절. 기준값은 시험 질문으로 정하고 기록한다.
- 검색된 청크가 질문의 기업·기간과 맞지 않는다.
- 답변의 핵심 주장에 연결할 청크가 없다 (근거 검증 통과 청크 0개).
- 공시에 없는 내용(전망, 비공개 정보, 뉴스 내용)을 요구한다.

시스템 프롬프트에 "제공된 공시 청크에 있는 내용만으로 답하고, 없으면 거절한다"를 명시한다.

## 평가 (가이드 10)

- 대표 질문 10개 내외, 그중 2~3개는 근거 없는 질문 → 올바르게 거절했는지 확인.
- 질문: `evaluation/rag_test_questions.json` (11개, 근거 없음 3개). 자동 지표: `evaluation/rag_eval_report.md`.
  답변·인용 전문은 `data/processed/rag_eval/answers.csv`(git 미추적)에 두고 사람이 `human_correct`를 채운다.
- 거절 기준값(`min_relevance`)은 `--retrieval-only`로 답변 가능/불가 질문의 최고 유사도를 본 뒤 정하고,
  값과 근거를 리포트에 적는다. 평가 질문으로 정한 값이므로 같은 질문의 거절률은 낙관적이라고 함께 적는다.
- 최종 수치는 `evaluation/evaluation_report.md`에 옮긴다.
