# Big4 전문서비스 산업 이슈 분석 — 최종 리포트

> 작성 2026-11-18. 이 리포트의 수치는 모두 실측값이며, 측정하지 않은 값은 "미확인"으로 적었다.
> 상세 기록: `evaluation/evaluation_report.md`(LLM 분류·RAG·결론 검수), `evaluation/gate_decision.md`(데이터 범위 결정),
> `evaluation/rag_eval_report.md`(QA 평가), `evaluation/spike_summary.md`(급증 배경).

## 1. 분석 목적

- **대상 산업:** 전문서비스(회계·감사·세무·컨설팅)
- **대상 기업:** PwC · Deloitte · EY · KPMG와 한국 회원 법인(삼일PwC · 딜로이트안진 · EY한영 · 삼정KPMG)
- **분석 기간:** 2023-11-01 \~ 2026-10-31. 연도 비교는 매년 1\~10월끼리 합니다(마지막 해가 10월까지라서).
- **대시보드 사용자:** Big4 동향을 보는 업계 실무자. 업계에서 지금 무엇이 보도되는지 빠르게 파악하고, 궁금한 사실은 공시 원문 근거로 확인하려는 사람을 상정했습니다.
- **핵심 질문:** **"이 산업에서 지금 무슨 일이 일어나고 있으며, 그 판단의 근거는 무엇인가."**
  - "무슨 일이 일어나고 있나"는 **뉴스**(변화 탐색)가 맡습니다.
  - "판단의 근거"는 **DART 공시**(사실 확인)가 맡습니다.
- **해석 원칙:**
  - 법인별 수치는 한국 회원 법인을 다룬 기사만 셉니다. 글로벌 브랜드 발표는 한국 법인의 실적으로 보지 않습니다.
  - Big4가 제출한 감사보고서는 **감사받은 고객사의 정보**입니다. Big4의 실적으로 표현하지 않습니다.

### 2-2. 수집 과정

1. **Day 1 게이트:**
   - Big4 자체 공시만으로는 기준(텍스트 추출 가능한 공시 30건, 공시 종류 3개)에 못 미쳤습니다(16건, 1종).
   - 그래서 공시 축을 **Big4가 제출한 고객사 감사보고서**로 넓혔습니다(분기 B-1).
   - 최종 판정은 텍스트 보유 146건, 공시 종류 3개로 충족했습니다. 기준은 조회 전에 정한 값에서 바꾸지 않았습니다.
2. **뉴스 검색어:** 4개 법인 × 별칭 2개 × 주제 14개 = 112개입니다(감리·제재·생성형·딜 자문·채용·정보보호 등).
   - 한 주제의 검색어가 네 법인 모두 기간 시작일까지 닿을 때만 그 주제를 썼습니다. 법인 간 비교를 공정하게 하기 위해서입니다.
   - 3차례 점검 끝에 112개 모두 잘림 없이 3년 전체를 수집했습니다.
3. **뉴스 정제:** 원본 응답 36,145건(검색어 간 중복 포함)을 다음 순서로 줄였습니다.
   - 기간 내 고유 기사 12,962건 → 완전 중복 464건 제외 → **12,498건**
   - 관련 기사 판정 → **2,581건**. 검색어에 법인명이 들어가 고객사 기사 속 감사인 언급 같은 무관 기사가 섞이기 때문입니다.
   - 법인 범위(한국 회원 법인 / 글로벌 네트워크 / 업계)도 표시했습니다.
4. **감사보고서 원문 표본:**
   - 2026년 3월 제출분, 정정 공시 제외, 법인당 30개 고객사(시드 42)
   - 처음에는 상장사로 제한하려 했으나 후보가 법인당 3건뿐이었습니다. 외부감사관련 목록은 대부분 비상장 외감 대상이라 제한을 풀었습니다.
5. **재실행 안전:** 모든 수집·적재 스크립트는 다시 실행해도 중복 적재가 생기지 않습니다. 원본은 `data/raw/`에 보존합니다.

### 2-3. 통합 스키마 (SQLite, `src/database/db_manager.py`)

뉴스와 공시를 한 테이블 `documents`에 담고, 분석 결과는 별도 테이블에 버전과 함께 저장합니다.

| 테이블 | 핵심 컬럼 | 설명 |
|---|---|---|
| `documents` | `doc_id`(NEWS_해시 / DART_접수번호), `source_type`(news/dart), `title`, `content`, `published_at`, `url`, `company_ids`, 공시 전용(`corp_code`, `rcept_no`, `report_nm`, `rcept_dt`), `content_hash`, `dup_group_id`, `is_relevant` | 뉴스·공시 통합. 뉴스는 `content_hash`, 모든 문서는 `url`이 유일 |
| `analysis_results` | `doc_id`, `sentiment`, `primary_category`, `issue_keywords`, `issue_summary`, `model_version`, `prompt_version`, `created_at` | LLM 분류 결과. (doc_id, prompt_version)이 키라 버전별로 보존 |
| `chunks` | `chunk_id`, `doc_id`, `chunk_index`, `section_title`, `text` | 공시 청크(벡터DB와 같은 ID) |
| `validation_samples` | `doc_id`, `prompt_version`, `reviewer`, 사람·LLM 라벨 | 표본 검수 |
| `insights` | `period`, `conclusion_text`, `evidence_doc_ids`, `reviewed_by` | 검수된 결론 |
| 대시보드 조회용 | `news_firm_scope`, `news_spikes`, `audit_filings_monthly`, `dart_corp_names` | 배치로 채우고 대시보드는 읽기만 |

- **스키마는 두 사람 사이의 계약입니다.** 변경은 별도 PR로 하고, 영향받는 계층을 PR 설명에 적었습니다.

### 2-4. 데이터 이용 조건

- 네이버 검색 API 약관은 결과 데이터와 그 파생물의 저장·가공·AI 입력을 금지합니다(약관 원문은 `gate_decision.md`).
- 팀은 이를 알고 **프로젝트 기간에만** 쓰고, 종료 시 삭제·차단하기로 결정했습니다.
- 그래서 저장소·리포트·화면에는 기사 원문·요약을 싣지 않고, 집계 수치와 제목·링크 수준까지만 둡니다.

## 3. EDA

### 3-1. 검색어 묶음별 기사량과 무관 기사 비중

수집한 기사 12,498건을 검색어 묶음(주제)별로 나눠, 산업·법인과 관련 있는 기사(정제본)와 무관한 기사의 비중을 확인했습니다.

| 검색어 묶음 | 전체 기사 | 관련 기사 | 무관 기사 비중 |
|---|---|---|---|
| 회계법인 AI | 3,598 | 1,121 | 68.8% |
| 회계법인 경쟁 | 3,017 | 331 | 89.0% |
| 회계법인 규제 | 2,610 | 277 | 89.4% |
| 컨설팅 트렌드 | 1,747 | 489 | 72.0% |
| 회계법인 인프라 | 1,526 | 363 | 76.2% |
| **합계** | **12,498** | **2,581** | **79.3%** |

- **무관 기사가 많은 이유:** 검색어에 법인명이 들어가서, 법인이 감사인이나 자문사로 **이름만 나오는** 기사가 많이 섞입니다(예: 고객사의 실적·제재 기사에 "감사인 ○○회계법인"만 언급). 특히 감리·제재·수임 같은 말을 쓰는 '규제'와 '경쟁' 묶음이 89%로 가장 높습니다.
- **분석 범위 판단:** 이후 모든 분석(기사량, 급증, LLM 분류, 대시보드)은 **관련 기사 2,581건**만 씁니다. 관련 여부는 법인이 기사의 주체인지(이름만 언급인지)와 기사 범위(한국 회원 법인 / 글로벌 / 업계)로 판정했습니다.
- **뺀 기사 유형:** 법인이 기사의 주인공으로 **직접 행동한** 기사만 남겼습니다(`src/preprocessing/firm_scope.py`). 아래는 뺐습니다.
  - 이름만 나오는 기사(고객사 기사 속 감사인 언급, 인물 경력 소개), 글로벌 본사·조직의 기사
  - 다른 회사 거래·사업의 **자문사·평가기관·매각 주관사**로 나오는 기사
  - 법인이 낸 **보고서·조사·설문**이 내용인 기사, 다른 기관 행사의 발표자로 나오는 기사, 연구 자료가 인용만 된 기사
- **이 기준이 뜻하는 것:** 대시보드의 기사량·카테고리·급증은 **"법인이 주체인 보도"** 입니다. 거래 자문이나 보고서 발간도 전문서비스 법인의 실제 사업 활동인데 빠져 있어, 산업 활동 전체를 대표하지 않습니다.
  - 검색어 주제에 '딜 자문'을 넣었지만 자문 역할 기사는 정제에서 빠집니다. 이 주제로 모은 기사 중 얼마나 빠졌는지는 세지 않았습니다.
- **판정의 한계:** 관련 판정은 규칙 기반이라 오류가 남습니다.
  - 검수 표본은 정제 후 남은 기사에서만 뽑았습니다. 그래서 남긴 기사가 맞는지는 봤지만, **뺀 기사 중 놓친 관련 기사(재현율)는 재지 않았습니다.**
  - Day 4 표본 검수에서 한 검수자가 100건 중 10건을 '관련없음'으로 봤습니다(4-3).
- **개선 방향:** 역할을 지우지 않고 유형(직접 활동 / 거래 자문 / 보고서 발간 / 행사 / 단순 언급)으로 남겨 "법인 직접 활동"과 "전문서비스 활동 전체"를 나눠 보고, 뺀 기사에서도 표본을 뽑아 검수합니다. 뉴스 데이터는 약관 때문에 프로젝트 종료 후 삭제하므로 이번에는 하지 않았습니다.

## 4. AI 기반 이슈 분석

### 4-1. 프롬프트 설계 (`src/analysis/llm_classifier.py`, prompt v1)

- **입력:** 관련 기사의 **제목 + 요약**입니다. 네이버 API는 본문을 주지 않습니다.
  - 같은 사건을 다룬 유사 기사 그룹은 **대표 기사 1건(1,742건)**만 분류하고, 결과를 그룹의 나머지 기사에 복사했습니다(결과 2,581건).
  - 이렇게 하면 같은 사건에 다른 라벨이 붙지 않고, 호출 수도 줄어듭니다.
- **정의를 프롬프트에 명시했습니다.**
  - **감성:** 기사 논조가 해당 산업·기업의 **사업 환경에 우호적인지**(긍정 / 중립 / 부정). 판단 예시도 넣었습니다(수주·출시는 긍정, 제재·소송은 부정, 인사·행사는 중립).

  - **이슈 키워드**(1\~3개)와 **한 문장 요약**도 함께 받습니다.
- **제약:**
  - "제목·요약에 없는 사실을 추가하지 않는다"를 명시했습니다.
  - 예시는 **가상의 문장**만 씁니다. 검수 표본을 예시로 쓰면 정확도가 부풀려지기 때문입니다.

### 4-4. 한계

- **감성 정의:** 감성은 기사 단위 논조라서, **법인에 대한 평가가 아닙니다.** 결론 검수에서 확인했습니다. 예를 들어 고객사의 손실을 다룬 기사에 새 감사인으로만 등장한 법인은, 그 법인을 비판하지 않아도 부정으로 분류됩니다.
- **입력:** 제목+요약뿐이라 맥락이 부족한 기사가 있습니다(검수자 A는 13건을 원문을 열어 판단).
- **검수 조건의 차이:** 검수자 A는 13건을 원문까지 열어 판단했고 B는 제목·요약만 봤습니다. 두 사람이 같은 조건으로 판정한 것이 아니어서, 정확도 범위(4-3)에는 사람 간 기준 차이와 정보량 차이가 함께 들어 있습니다.
- **지표의 범위:** 정답 집합을 합의로 확정하지 않아 정확도만 보고했습니다. 분류별 정밀도·재현율·F1과 혼동행렬은 만들지 않았습니다.
- **중복 묶기:** 유사 기사 묶기가 표현·표기(영문/한글)가 다른 같은 사건 보도를 묶지 못합니다. 사건 수가 실제보다 많게 셀 수 있습니다.
- **재현성:** temperature 기본값이라 다시 실행하면 결과가 달라질 수 있습니다. 검수와 보고는 저장된 1회 실행 결과를 기준으로 했습니다.
- **개선 방향:**
  - 경계 사례를 정의에 추가하고(프롬프트 v2), 새 표본으로 재측정
  - 법인 대상 감성을 측정하려면 프롬프트 v2, 전체 재분류, 재검수가 필요합니다

### 4-5. 심화: 기간별 이슈 자동 요약

- **무엇:** 분기마다 그 기간의 핵심 이슈를 LLM이 한 줄 요약(headline)과 이슈 1\~3개로 정리합니다. Issue Analysis 맨 위 "기간별 핵심 이슈"에 표시됩니다.
- **방법:**
  - 분기마다 기사가 많은 사건 상위 8개를 **저장된 분류 결과**(카테고리·감성·키워드·한 줄 요약)로 정리합니다. 그 분기의 사람이 쓴 급증 배경도 더합니다.
  - LLM(`issue-v1`)이 사건 번호를 인용해 요약합니다. **기사 제목·URL은 보내지 않고**, 근거 기사는 인용한 사건 번호로 코드가 연결합니다.
  - 결론 문장과 같은 검수 흐름입니다. 두 사람이 근거 기사와 대조해 고치고, 둘 다 승인한 분기만 적재합니다.
- **결과:** 13개 분기(2023-Q4 \~ 2026-Q4) 모두 두 사람 승인으로 적재했습니다.
  - 검수에서 고친 예: 업무협약 단계인데 서비스를 이미 제공하는 것처럼 쓴 문장을 "~하기로 했다"로 고쳤습니다.
  - 같은 협약의 기사 두 건이 다른 그룹으로 나뉜 것도 확인했습니다.
- **관찰:** headline 13개 중 10개에 'AI'가 들어가고, 2024-Q3부터 2026-Q3까지 9개 분기 연속입니다. 기사가 많은 사건 중심의 요약이라 **보도 노출의 흐름**이며, 법인의 사업 비중을 뜻하지 않습니다.
- **한계:**
  - 입력이 LLM 분류 결과(한 줄 요약)라 그 정확도(요약 사실 일치 0.897)의 영향을 받습니다.
  - 다시 실행하면 문장이 달라질 수 있습니다.
  - 분기별 수정 건수는 기록하지 않았습니다.

### 5-3. 근거 표시 방식

- **답변 카드:** 근거 청크마다 카드 1장에 공시명·제출일·접수번호·DART 원문 링크·절 경로를 보여줍니다.
- **인용 표시:** 청크 원문 안에서 **원문 대조를 통과한 인용 구절만 굵게** 표시합니다. 그래서 "합계 791 768" 같은 짧은 숫자도 어느 표의 값인지 보입니다.
- **고객사 감사보고서 근거:** "고객사(감사 대상)"와 "감사인(제출)"을 나눠 적고, "감사인의 실적이 아님"을 표시합니다.
- **거절:** 거절 문구와 사유(유사도 / 모델 거절 / 인용 불일치)를 보여줍니다. 대조에 실패한 인용은 진단용으로 접어 둡니다.
- **안내:** 질문의 법인명을 인식했거나 오타를 고쳤거나 선택한 법인과 달랐으면 화면에 알립니다.
- **답변 속 숫자 확인:** 인용이 원문에 있다고 답변 전체가 근거를 따르는 것은 아닙니다(인용 "매출 1,000억 원" + 답변 "전년 대비 30% 성장"). 그래서 답변의 숫자(2자리 이상)를 인용한 청크 원문·공시 정보·질문과 대조하고, 없으면 **"확인 필요"** 로 표시합니다.
  - 거절하지 않는 이유: 단위 환산이나 합계처럼 맞는 계산도 원문에 없는 숫자가 되기 때문입니다.
  - 숫자가 없는 주장(예: "증가 추세다")은 검사하지 못합니다.
  - 이 장치는 평가(5-2, 5-4)를 마친 뒤 추가해서 위 평가 수치에는 반영되지 않았습니다.

### 5-4. 심화: 검색 고도화 (하이브리드 검색 + LLM 리랭킹)

- **동기:** 실패의 대부분이 "답할 수 있는데 거절"이었고, 원인은 질문과 공시의 용어 차이였습니다(Q04).
- **구성:**
  - **하이브리드:** 벡터 검색에 BM25 키워드 검색을 더해 두 순위를 RRF로 결합합니다. 한국어는 단어 안 글자 2-gram으로 나눕니다.
  - **리랭킹:** 결합한 후보 20개를 LLM이 질문 관련성 순으로 다시 매겨 8개를 씁니다.
  - **거절 기준:** 1차 거절은 세 방식 모두 벡터 유사도 0.50으로 같게 두었습니다.
- **평가:** 기존 질문 11개에, 검색 고도화 뒤 **새 질문 6개(holdout)**를 더했습니다. 공시 절 제목과 다른 말로 묻는 질문 4개와 근거 없는 질문 2개입니다. 새 질문은 설정을 맞추는 데 쓰지 않았고, DART 원문과 대조해 판정했습니다(거절 = 오답).

| 방식 | 기존 질문 정답 | 새 질문 정답 | 전체 정답 | 근거 없는 질문 거절 |
|---|---|---|---|---|
| 벡터 (기존) | 7/8 | 3/4 | 10/12 | 5/5 |
| 벡터 + 키워드 | 7/8 | 2/4 | 9/12 | 5/5 |
| **벡터 + 키워드 + LLM 재정렬** | 7/8 | **4/4** | **11/12** | 5/5 |

- **결과:** 세 방식 모두 답한 질문은 전부 정답이었고, 차이는 답할 수 있는 질문을 거절했는지에서 났습니다.
  - LLM 재정렬만 '징계' 질문(공시 절은 '징계내역')을 찾았습니다.
  - 키워드만 더하면 '법적 분쟁' 질문(공시 절은 '소송')까지 거절해 오히려 낮았습니다.
- **결정:** 대시보드 QA의 기본 검색을 **벡터 + 키워드 + LLM 재정렬**로 바꿨습니다. 화면에 검색 방식을 표시합니다.
- **한계:**
  - 새 질문이 4개뿐이라 차이가 우연일 수 있습니다.
  - Q04(감독기관 조치 ↔ 감리결과)는 세 방식 모두 실패했습니다. 겹치는 글자가 없기 때문입니다.
  - 질문마다 LLM 호출이 1회 늘어납니다(실제 비용 미확인).
  - 이번 측정에서는 Q05가 정답으로 판정돼 기존 질문이 7/8입니다(11-17 측정은 6/8). 모델 답이 실행마다 달라질 수 있습니다.
- **추가 검증 (holdout2, 2026-11-19):** 방식을 정한 뒤 만든 새 질문 15개로 다시 쟀습니다. 답변 가능 11개 중 **10개 정답**, 근거 없는 질문 **4/4 거절**, 답한 질문의 오답은 0이었습니다.
  - 실패 1건은 두 법인을 한 번에 묻는 질문(H14)의 거절로, 기존에 알려진 한계와 같습니다.
  - 숫자 확인 경고는 정답 2건에 떴고 둘 다 잘못된 경고였습니다(계산한 차이, 인용하지 않은 청크의 기수). 틀린 숫자를 잡는지는 이번 질문으로는 측정되지 않았습니다.

## 7. 회고

### 7-1. LLM 활용 시 발생한 문제와 대응

**환각(hallucination) 대응 요약.** 이 프로젝트에서 LLM이 사실과 다른 내용을 만들 수 있는 지점은 세 곳이었고, 모두 "모델 출력을 그대로 쓰지 않는" 장치를 두었습니다.

| 지점 | 환각 유형 | 장치 |
|---|---|---|
| 뉴스 분류·요약 | 제목·요약에 없는 사실을 덧붙임 | 프롬프트에 금지 명시, 사람 표본 검수(요약 사실 일치 0.897) |
| 공시 QA | 공시에 없는 수치·사실로 답함 | 인용 구절을 검색된 원문과 문자열 대조, 통과한 인용이 없으면 거절, 근거 없는 질문 거절 5/5. 답변 숫자가 인용 원문에 없으면 "확인 필요" 표시(숫자 없는 주장은 미검사) |
| 결론·분기 요약 | 출처나 숫자를 지어냄 | 사실·사건 번호만 인용하게 하고 근거 문서는 코드가 연결, 숫자 대조("확인 필요"), 두 사람 승인 문장만 표시 |


| 문제 | 대응 |
|---|---|
| 모델이 temperature 0을 거부해 같은 입력도 결과가 달라질 수 있음 | 기본값으로 호출하고, 저장된 1회 실행 결과로 검수·보고. 재현성 한계로 기록 |
| 응답 형식이 틀릴 수 있음 | JSON 스키마 검증 + 1회 재시도, 실패는 사유와 함께 기록(분류 실패 0건) |
| 같은 보도자료를 옮긴 기사들에 다른 라벨이 붙고 비용이 늘어남 | 유사 기사 그룹의 대표만 분류하고 결과를 복사 |
| 카테고리·감성 경계가 사람에게도 모호함 | 정확도를 두 검수자 기준 범위로 보고. 경계 사례는 다음 프롬프트 개선 과제로 기록 |
| 감성이 법인 평가처럼 읽힘(결론 검수에서 발견) | 감성 정의를 차트 주석에 명시하고 결론에서 제외. 법인 대상 감성은 한계로 기록 |
| RAG: 표준 문단이 검색 상위를 차지 | 반복되는 표준 문단 498종을 청킹 전에 제거 |
| RAG: 상위 제목이 버려져 표가 검색되지 않음 | 절 제목을 상위 제목까지 이은 경로로 저장하고 재임베딩 |
| RAG: 표를 찾고도 띄어쓰기 차이로 인용 대조 실패 → 거절 | 인용 대조는 공백만 무시. 프롬프트 rag-v4에서 표는 원문 그대로 인용하게 함 |
| RAG: 법인명 띄어쓰기·오타·이전 선택값 때문에 거절 | 질문 속 법인 인식(띄어쓰기 무시), 자모 거리 오타 교정, 질문 속 법인이 선택과 다르면 질문을 따르고 알림 |
| RAG: 질문과 공시의 용어가 다르면 답할 수 있는데도 거절 | 키워드(BM25) 결합 + LLM 재정렬, 새 질문(holdout)으로 전후 비교 → 새 질문 3/4 → 4/4. 용어가 전혀 겹치지 않는 Q04는 미해결 |
| 결론 초안이 출처나 숫자를 지어낼 위험 | 사실 번호를 인용하게 하고 근거 문서는 코드가 연결. 문장 숫자가 인용 사실에 없으면 "확인 필요" 표시. 두 사람이 모두 승인한 문장만 적재 |
| 결론 초안이 길고 숫자가 많아 한눈에 읽기 어려움 | 사람이 핵심 수치만 남겨 3개로 줄이고, 세부 수치는 차트로 넘김 |
| 뉴스를 LLM에 넣는 것의 약관 문제 | 분류는 기간 중에만, 결론 초안에는 기사 제목·요약을 보내지 않음. 종료 시 결과 삭제 |
